# EXECUTION ORDER 01: Monorepo Scaffolding

### Task 1: Generate the Chassis

Open your terminal in your target workspace directory and instantiate Turborepo using `pnpm` (the required package manager for this architecture):

**Bash**

```
pnpm dlx create-turbo@latest car-shop --package-manager pnpm
cd car-shop
```

*(When the CLI asks, accept the defaults. We are about to surgically alter them).*

### Task 2: Purge the Boilerplate

The standard Turbo generator includes a sample documentation site we do not need. Kill it, then build our precise skeleton:

**Bash**

```
# Purge the unneeded app
rm -rf apps/docs

# Scaffold our internal package directories
mkdir -p packages/db/prisma packages/schema/src packages/types/src packages/api-client/src packages/design-tokens
```

### Task 3: Lock the Workspace Map

Open the `pnpm-workspace.yaml` file in your root directory and ensure it reads strictly as follows:

**YAML**

```
packages:
  - 'apps/*'
  - 'packages/*'
```

### Task 4: Stand up the Database Package

Navigate into `packages/db/` and create its unique `package.json`:

**JSON**

```
{
  "name": "@carshop/db",
  "version": "0.1.0",
  "private": true,
  "scripts": {
    "generate": "prisma generate",
    "db:push": "prisma db push"
  },
  "dependencies": {
    "@prisma/client": "5.10.0"
  },
  "devDependencies": {
    "prisma": "5.10.0"
  }
}
```

Now, create the database schema file at `packages/db/prisma/schema.prisma` and paste the exact production PostgreSQL Prisma code we finalized in our last transmission.

Once saved, return to the **root** `car-shop/` directory and bind the packages together:

**Bash**

```
pnpm install
```

### Checkpoint 01 Verification

To pass this gate, spin up a local PostgreSQL database (via Docker or your local Postgres install), create a `.env` file inside `packages/db/.env`, and add your connection string:

**Extrait de code**

```

```

Run this command from the root of your workspace:

**Bash**

```
pnpm --filter @carshop/db generate
```
